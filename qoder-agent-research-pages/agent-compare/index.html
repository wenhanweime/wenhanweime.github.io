🔁Agent Loop / 对话循环

QoderWork 证据 main.pretty.js(反编译美化)；OpenClaw dist/*.runtime；Hermes hermes-agent/*.py。

0. 一句话差异

  • QoderWork：固定单引擎。renderer 经 tRPC → UnifiedChatExecutor.executeTask → 自家 @ali/qoder-agent-sdk-next 经 ProcessTransport 以 stdio + stream-json 驱动唯一的 qodercli 二进制；主进程消费事件流回推 GUI。
  • OpenClaw：多引擎编排器。runAgentTurnWithFallback 包模型回退，底下要么 spawn 外部 CLI（claude/codex/cursor/gemini/qwen，runCliAgent），要么用嵌入式 @mariozechner/pi-ai；消费统一事件流回推 IM。
  • Hermes：自持进程内循环。run_conversation 自己跑 while 循环，直接调 provider 适配器 API，迭代预算 + 中断 + /steer + 护栏全自管。

三者恰好是「单引擎绑定 / 多引擎编排 / 自持循环」三种 agent 运行时范式。

0.5 认知范式：ReAct 还是 Think-Plan-Act？（核心）

结论：三者底层都是 ReAct（交错的「推理→工具→观察」单环，由 stopReason==toolUse / finish_reason==tool_calls 驱动是否再转一圈；都没有独立的"先出完整计划再照计划执行"的 plan-and-execute 引擎）。差别在 ReAct 之上叠了多少显式规划脚手架——这条轴从重到轻是 QoderWork ＞ Hermes ＞ OpenClaw：

底层环 ReAct（qodercli 内） ReAct（pi-ai stopReason） ReAct（while + finish_reason）

各家证据

  • QoderWork = ReAct 之上压了最重的"计划"层：系统提示词强制 TodoWrite（main.pretty.js:79088 "MUST use TodoWrite for virtually ALL tasks that involve tool calls"），规定工作流 Review Skills / AskUserQuestion → TodoWrite → Actual work（:79098）+ 收尾 <verification_step>；另有独立 plan 模式（mode:plan|agent，plan 下只能改 .md、其余工具被 block，靠 ExitPlanMode 工具退出进入执行，:42694/42794/78404）。所以它体感最像 think-plan-act：先列 TODO（计划）→逐项做（ReAct）→验证；但本质仍是 ReAct，TODO 只是"活计划清单"而非死计划。IM 模式下禁用 TodoWrite（:67015，无 widget 可渲染）。
  • ⚠️ 不是黑盒：以上不止来自主进程的提示词拼装——qodercli 二进制（Bun --compile，未开 --bytecode，JS 源码原样内嵌）里可直接 strings 抽到：系统提示词 "You are QoderWork, a desktop agentic assistant developed by Qoder team..."、# Identity 段、ExitPlanMode/TodoWrite/AskUserQuestion 提示原文（"use this tool to clarify requirements or choose between approaches BEFORE finalizing your plan"）、以及与 Claude Code 一致的工具描述（"Executes a given bash command and returns its output."/"Reads a file from the local filesystem..."）。即 qodercli 的 ReAct+plan 范式是可从二进制证实的，非推测（见下 §6.3 方法）。
  • OpenClaw = 最精简的纯 ReAct：pi-ai 按 stopReason==="toolUse"?继续:停（pi-embedded:99863）单环跑，无常驻 todo/计划工具；规划靠思考档位与内联指令临时调节——thinkLevel: off/high/xhigh（xhigh 受 supportsXHighThinking 门控）、用户消息里写 /think//reasoning//plan/fast 等 directives 即时改本轮推理强度。契合 IM 短对话：少仪式、要快。
  • Hermes = 带显式推理标签的 ReAct，计划按需上：模型产出 <think>/<thinking>/<reasoning>/<thought> 块（think_scrubber/convert_scratchpad_to_think）= reason-before-act；todo_tool（VALID_STATUSES=pending/in_progress/completed/cancelled，write(merge|replace)）是可选活计划；真正的"先规划"留给 kanban（kanban_decompose/kanban_specify/kanban_swarm）处理大任务/多 agent。即轻任务直接 ReAct，重任务才显式分解。

3. QoderWork 实现（main.pretty.js）

  • 入口 chatStreamRouter.submitMessage（:88363）→ unifiedExecutor.submitOrQueue（运行中入队/空闲直跑）→ ChatSessionService（:78547）→ UnifiedChatExecutor.executeTask（:83535）。
  • executeTask 组装 SDK options Pr（:84050）：systemPrompt/agents/mcpServers/skills/permissionMode(plan|default)/canUseTool/hooks/pathToQoderCLIExecutable。
  • qoder-agent-sdk 的 ProcessTransport.buildArgs（sdk:410）发 --print --output-format stream-json --input-format stream-json --permission-prompt-tool stdio 等，spawn qodercli。
  • 主进程 for await 消费事件（result/compact_boundary/error/text-delta），broadcastStreamChunk 推 renderer；权限经 createCanUseToolCallback(:42749) 反向门控。
  • 特征：单一引擎、桌面 GUI 回推、强权限门 + hooks（与 Claude Code 形态同构）。

4. OpenClaw 实现（dist）

  • runAgentTurnWithFallback（agent-runner.runtime:338）while(true) 消费事件；runWithModelFallback 模型链；CLI provider 走 runCliAgent（pi-embedded）spawn 外部 agent，非 CLI 走嵌入 pi-ai（各 provider stream fn，stopReason: toolUse→继续，:99863）。
  • 8 个生命周期 hook（:10282-10335）；runner 负责 typing/dedupe/记忆 flush/HEARTBEAT 静默。

5. Hermes 实现（hermes-agent）

  • run_conversation（conversation_loop.py:351），主循环 while api_call_count<max && budget.remaining>0（:796）；IterationBudget+grace、_interrupt_requested、_drain_pending_steer、_interruptible_api_call（:1308）、_execute_tool_calls→execute_tool_calls_concurrent（tool_executor.py:110，线程池 + tool_search 桥接展开 + scope 门，注释自承"OpenClaw lesson"）；guardrail halt（:3835）。

6. 三方结论

  • 谁跑循环：QoderWork 把循环放进 qodercli（但其 JS 源码内嵌可提取，非真黑盒，见 §6.3）；OpenClaw 把循环外包给可替换引擎（甚至外部 coding CLI）；Hermes 自己跑、全透明可控。
  • 回推终端：QoderWork=桌面 GUI；OpenClaw=IM；Hermes=CLI/TUI（+TTS）——三种入口。
  • 可控性梯度：Hermes（最细，预算/中断/steer/护栏进程内）> QoderWork（permissionMode+hooks，循环在 CLI 内但可还原）> OpenClaw（交给下层引擎，自身专注渠道侧）。
  • 交叉印证：QoderWork 的 SDK 形态 ≈ Claude Code（qodercli 二进制内含 @anthropic-ai/claude-code、CLAUDE_CODE_AGENT_RULE_DISABLED、同款工具描述）；OpenClaw 能把 Claude Code/Codex 当引擎编排；Hermes 代码显式引用"OpenClaw lesson"——三者同处一个相互借鉴的 agent runtime 生态。

6.3 如何"看穿" qodercli（方法 + 可达性）

qodercli 是 Bun --compile 单文件可执行（Mach-O arm64, 99MB），但未启用 --bytecode——transpile 后的 JS 源码原样内嵌。因此它的 agent loop 不是机器码黑盒，可由浅入深四条路还原：

通道 拿到什么 状态
① SDK 协议（qoder-agent-sdk） CLI 参数 + stream-json 事件契约（loop 的 I/O 边界） ✅ 已还原
② 主进程拼装（main.pretty.js） 喂给 qodercli 的 systemPrompt/工具/hooks/permissionMode（loop 的全部输入） ✅ 已还原
③ 二进制 strings 提取 qodercli 内嵌 JS 源码：系统提示词、工具实现、plan/todo/think 逻辑、事件状态机 ✅ 可提取（18MB 可读 JS / strings -n 60）
④ 动态观测 --debug/debugFile + 喂 stream-json 实跑，记录真实事件序列 可选

实测（Resources/bin/qodercli）：

$ strings -n 60 qodercli > qodercli.js   # 抽出 ~18MB 可读 JS
OHE="You are QoderWork, a desktop agentic assistant developed by Qoder team..."   # 系统提示词
"...plan mode, use this tool to clarify requirements ... BEFORE finalizing your plan"  # ExitPlanMode
"Executes a given bash command and returns its output."  / "Reads a file from the local filesystem..."  # 工具

结论：把 qodercli 当主进程同法处理（strings → 切出 JS 区段 → js-beautify → 顺函数读）即可做出与 §3/§4/§5 同级的函数级 agent-loop 章节。所以「难以推测其 agent loop」并不成立——它甚至比 OpenClaw 的外部 CLI provider（claude/codex 闭源二进制，部分仅协议可见）更完全可还原。真正还原成本只是工程量（99MB 里切 JS、去 Bun 运行时噪声），不是信息缺失。

6.4 从 qodercli 二进制实读出的循环内核（已提取，非推测）
